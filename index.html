DBMS Documentation

Database design and project reference.

1. Project Abstract

AirMetric is an air-quality monitoring and historical analysis system designed to organize sensor stations, air-quality readings and pollution alerts using a relational database model.

2. ER Relationships

USERS
PK user_id
name, email
password_hash, role
SENSORS
PK sensor_id
sensor_name, location
latitude, longitude, status
READINGS
PK reading_id
FK sensor_id
recorded_at, pm25, pm10
co2, aqi
ALERTS
PK alert_id
FK sensor_id
FK reading_id
alert_type, severity, status

Relationships: One sensor has many readings. One sensor can have many alerts. A reading can generate alerts. Users are stored separately for authentication and authorization.

3. Functional Dependencies

  • Users: user_id → name, email, password_hash, role, created_at.
  • Sensors: sensor_id → sensor_name, location, latitude, longitude, status, created_at.
  • Readings: reading_id → sensor_id, recorded_at, pm25, pm10, co2, aqi.
  • Alerts: alert_id → sensor_id, reading_id, alert_type, message, severity, created_at, status.

4. Normalization

1NF: Each field stores one value and every row has a unique key.

2NF: Each table uses a single-column primary key, avoiding partial dependencies.

3NF: Sensor details are stored in sensors rather than repeated in readings. User details are stored separately.

5. SQL CRUD Examples

INSERT INTO sensors
(sensor_name, location, latitude, longitude, status)
VALUES ('Sensor A', 'Campus', 17.385, 78.486, 'Active');

SELECT * FROM sensors;

UPDATE sensors SET status = 'Inactive'
WHERE sensor_id = 1;

DELETE FROM sensors WHERE sensor_id = 1;

SELECT sensor_id, AVG(aqi) AS average_aqi,
MAX(aqi) AS highest_aqi
FROM readings GROUP BY sensor_id;

6. Sample View

CREATE VIEW daily_air_quality_summary AS
SELECT DATE(recorded_at) AS reading_date,
COUNT(*) AS total_readings,
AVG(aqi) AS average_aqi,
MAX(aqi) AS highest_aqi
FROM readings
GROUP BY DATE(recorded_at);

7. Testing Checklist

  • Add, search, edit and delete a sensor using Admin access.
  • Add, filter, edit and delete a reading using Admin access.
  • Verify chart and report updates.
  • Resolve an alert and check alert counts.
  • Verify User access is read-only.
  • Test login and persistence after refresh.
